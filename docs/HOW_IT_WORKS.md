# Как работает Hephaestus — объяснение для гуманитариев

Представьте себе огромную библиотеку вакансий. Вся эта библиотека говорит на одном языке: "Требуется Java", "нужен Python", "ищем React разработчика". Но если посчитать, то одно и то же умение называется по-разному: "JavaScript", "JS", "Яваскрипт", "js" — это все один навык, но записан четырьмя способами.

**Hephaestus** — это система, которая:

1. Берёт все вакансии
2. Читает их как умный ассистент и понимает: "Ах, здесь требуется Java"
3. Нормализует это (переводит в единый формат)
4. Организует по профессиям и направлениям
5. Помогает увидеть, как развиваться в карьере

---

## Система по слоям (как матрёшка)

### Слой 1: Сырые вакансии

Это первый уровень — вакансии в том виде, в котором они лежат на HeadHunter. Не обработаны, не проверены, просто скачаны:

```
[Вакансия 1]
Название: "Senior React Developer"
Описание: "Ищем разработчика с опытом React, 
           Redux, TypeScript, REST API..."

[Вакансия 2]
Название: "Frontend разработчик"
Описание: "Требуется знание JavaScript, React, CSS Grid..."
```

Компьютер пока ничего не знает про то, какие навыки требуются.

---

### Слой 2: Извлечённые навыки (требуют проверки)

Система прочитала описание вакансии и выделила навыки. Но они ещё не проверены:

```
Из вакансии 1 извлечено:
- React (неповеренный)
- Redux (неповеренный)
- TypeScript (неповеренный)
- REST API (неповеренный)

Из вакансии 2 извлечено:
- JavaScript (неповеренный)
- React (неповеренный) ← Видите, "React" появился ещё раз!
- CSS Grid (неповеренный)
```

Пока это просто список "что система подумала". Вам предстоит это проверить.

---

### Слой 3: Нормализованные навыки (справочник)

Это то, что осталось после вашей проверки. Один правильный список:

```
✓ React
  - Синонимы: "react.js", "React.js", "Реакт"
  - Тип: JavaScript фреймворк
  - Уровень: может быть Junior, Middle, Senior
  - Направление: Frontend
  - Профессия: Frontend Developer
  - Встречается в вакансиях: 1,234 раза

✓ JavaScript
  - Синонимы: "JS", "js", "Яваскрипт", "javascript"
  - Тип: Язык программирования
  - Уровень: Junior/Middle/Senior
  - Направление: Frontend, Full Stack
  - Профессия: Frontend Developer, Full Stack Developer
  - Встречается в вакансиях: 5,678 раз
```

В этом слое каждый навык уникален. "React" — это один навык, а не десять копий.

---

### Слой 4: Связи и траектории

На этом слое система понимает, как навыки связаны:

```
"Если требуется React, то обычно требуется и JavaScript" 
→ Навыки связаны

"Для Junior Frontend нужны: HTML, CSS, JavaScript"
"Для Middle Frontend нужны: React, TypeScript, REST API"
"Для Senior Frontend нужны: архитектура, менторство, системное мышление"
→ Это карьерная траектория
```

## Жизненный цикл одного навыка

### Сценарий: В вакансии появилась "React.js"

**День 1. Вакансию скачали**
```
Вакансия на HeadHunter → загрузилась в базу
Статус: сырая данные, необработанная
```

**День 1, час 2. Система прочитала описание**
```
AI говорит: "Я вижу 'React.js' в описании"
Создаётся запись: "React.js" (требует проверки)
Статус: в очереди на модерацию
```

**День 2. Модератор (вы) проверяете**
```
Вопрос: "React.js" — это новый навык или синоним существующего?

Вариант A: Это новый навык
→ Добавляете в справочник с нужными параметрами

Вариант B: Это то же самое, что "React"
→ Связываете как синоним
→ Теперь система знает: "React.js" = "React"

Вариант C: Это неправильно извлечено (ошибка AI)
→ Отклоняете и удаляете
```

**День 3. Навык в справочнике**
```
Справочник обновлён:
✓ React
  Синонимы: React.js, react.js, Реакт
  
Теперь каждый раз, когда система видит "React.js", 
она знает, что это = "React"
```

## Как система выполняет работу

### Шаг 1: Получить вакансии

Система подключается к HeadHunter и говорит: "Покажи все вакансии про 'React' или 'JavaScript'". Скачивает описания, названия, зарплаты, требования.

**Что вам нужно:** Просто нажать одну кнопку "Загрузить с HH"

### Шаг 2: Прочитать и понять

Система использует "умный мозг" (нейросетевую модель) для извлечения навыков. Модель обучена на миллионах текстов и может сказать: "Вот здесь требуется React, а здесь требуется TypeScript".

**Аналогия:** Как если бы вы нанимали очень опытного рекрутера, который за несколько секунд прочитает вакансию и выпишет все требуемые навыки.

**Что вам нужно:** Просто дождаться. Система работает сама.

### Шаг 3: Проверить и утвердить

Вы открываете список "Требует проверки" и видите:

```
□ React (из вакансии "Senior React Developer")
□ JavaScript (из той же вакансии)
□ CSS (из вакансии "Frontend Developer")
```

Для каждого навыка нужно решить:
- Это правильно извлечено? (Да/Нет)
- К какой профессии это относится? (Frontend, Backend, etc)
- Какой это тип? (язык, фреймворк, база данных)

**Что вам нужно:** Кликнуть "Одобрить" или "Отклонить"

### Шаг 4: Система обновляется

Когда вы одобрили навыки, система:
- Добавляет их в окончательный справочник
- Связывает синонимы
- Подсчитывает статистику (сколько раз каждый навык встречается)
- Готовит информацию для карьерных траекторий

**Что вам нужно:** Ничего. Система работает автоматически.

## Почему это нужно?

### Проблема без системы

Если просто сложить все вакансии, получится хаос:
- 5,000 вакансий говорят про "JavaScript"
- 3,000 про "JS"
- 2,000 про "javascript"
- 500 про "Яваскрипт"

Итого 10,500 вакансий требуют один навык, но компьютер видит его как четыре разных.

**Результат:** Невозможно дать верные советы типа "68% вакансий требуют JavaScript".

### Решение с Hephaestus

Система нормализует всё:
- JavaScript ← JS, javascript, Яваскрипт
- React ← React.js, react.js, Реакт

**Результат:** Можно сказать "68% вакансий требуют JavaScript" и это будет правда.

## Как синонимы работают

Система "знает", что это одно и то же:

```
Все эти названия = React:
- React
- react.js
- React.js
- Реакт
- Реакт JS
- (любое написание)

Когда система видит "react.js" в новой вакансии:
1. Нормализует: "react.js" → "react" (по правилам)
2. Ищет в справочнике: "Есть ли 'react'?"
3. Находит: "Да, это React из справочника"
4. Использует существующий навык, а не создаёт новый
```

## Технический взгляд (кратко для любопытных)

### Нормализация (что происходит за сценой)

```
"React.Js" → "react.js" (маленькие буквы)
           → "reactjs" (убрать точку)
           → найти похожее в справочнике
           → если похоже на 95%, то это синоним
```

### Синонимы определяются по

1. **Точное совпадение после нормализации**
   - "JavaScript" и "javascript" → то же самое

2. **Расстояние Левенштейна** (сколько букв нужно изменить)
   - "Reaktc" vs "React" → 1 ошибка → скорее всего опечатка

3. **Семантическое сходство** (AI понимает смысл)
   - "JS" и "JavaScript" → семантически одно и то же, хотя написание разное

4. **Составные части**
   - "React.js" = "React" + ".js" → явно один навык с точкой и js
